# RIver AGI 系统实现说明书

## 1. 项目定位

RIver AGI 是一个“对话式数据智能分析平台”。用户上传 Excel、CSV、JSON 等数据后，系统自动完成：

```text
数据上传 → 数据识别 → 数据质量分析 → 自动标注 → 安全风险检测
→ 自动生成图表 → 市场需求预测 → AI解释和报告生成
```

第一阶段重点不是实现真正的通用人工智能，而是实现稳定、可追溯的数据分析与 AI 辅助决策闭环。

## 2. 推荐总体架构

建议先采用“模块化单体 + 独立算法服务”，不要一开始拆成大量微服务。

```text
Vue 前端
   ↓ REST API / SSE
Spring Boot 后端
   ├── 用户、权限、数据集管理
   ├── 文件上传和数据分析任务
   ├── 标注任务和质量管理
   ├── 预测任务和模型管理
   ├── 安全扫描和操作审计
   ├── 报表和图表接口
   └── Spring AI + DeepSeek 对话编排
           ↓ HTTP
Python FastAPI 算法服务
   ├── 数据统计分析
   ├── 异常检测
   ├── 特征工程
   ├── 需求预测
   └── 模型评估和重训

数据层：PostgreSQL/MySQL + Redis + MinIO
异步任务：RabbitMQ
部署：Docker Compose，后续再考虑 Kubernetes

## 5. 核心业务流程

### 5.1 上传和数据分析流程

```text
前端上传文件
→ Spring Boot 保存文件到 MinIO
→ 写入 dataset 和 task 记录
→ RabbitMQ 发布解析任务
→ 后台解析 Excel/CSV/JSON
→ 识别字段类型、缺失值、重复值、异常值
→ 执行敏感信息扫描
→ 保存数据画像
→ 前端查询任务状态和分析结果
```

### 5.2 对话式分析流程

```text
用户发送问题
→ Spring AI 发送问题、数据集摘要和可用工具给 DeepSeek
→ DeepSeek 返回工具调用意图
→ 后端校验用户权限和参数
→ 后端执行真实的数据分析/预测/安全扫描
→ 将工具结果返回 DeepSeek
→ DeepSeek 生成文字解释
→ 后端返回文字、图表配置、任务结果和风险提示
```

AI 工具示例：

```text
inspect_dataset(datasetId)
profile_dataset(datasetId)
scan_sensitive_data(datasetId)
detect_outliers(datasetId, field)
recommend_charts(datasetId)
create_prediction_task(datasetId, targetField, timeField)
explain_prediction(predictionId)
generate_report(datasetId, resultIds)
```

### 5.3 数据标注流程

```text
创建标签体系
→ 创建标注任务
→ 分配标注员
→ AI预标注
→ 人工确认和修改
→ 审核员抽检
→ 冲突进入仲裁
→ 计算标注质量
→ 发布为训练数据集
```

第一版优先实现表格和文本标注；图片、视频标注作为第二阶段扩展。

### 5.4 市场需求预测流程

```text
选择数据集、时间字段和预测目标
→ 后端校验数据是否适合预测
→ 调用 Python 算法服务
→ 数据清洗和特征工程
→ 训练基线模型和 LightGBM/XGBoost 模型
→ 计算 MAE、RMSE、MAPE 等指标
→ 保存模型版本和预测结果
→ 生成趋势图、置信区间和解释
```

第一版先支持一个明确的预测目标，例如按日期预测销量。不要一开始实现所有模型。

### 5.5 安全风险分析流程

```text
上传或选择数据集
→ 字段名规则识别
→ 正则和校验算法识别手机号、身份证、邮箱等
→ NLP/OCR 识别文本和图片中的敏感信息
→ 计算字段组合关联风险
→ 生成高/中/低风险结果
→ 提供脱敏、删除、加密、限制导出的建议
→ 写入安全扫描记录和审计日志
```

## 8. 前后端和数据库交互规则

```text
Vue 页面
→ Axios 调用 Spring Boot API
→ Spring Boot 校验 JWT 和数据权限
→ Service 执行业务逻辑
→ Mapper/Repository 访问 PostgreSQL
→ 大文件从 MinIO 读取
→ 大任务写入 RabbitMQ 异步执行
→ 前端通过轮询或 SSE 获取进度
```

禁止前端直接访问数据库、MinIO 管理接口或 DeepSeek API。

禁止 AI 直接拼接并执行未审核的 SQL。需要通过后端的数据查询工具，并限制表、字段、行数和查询时间。

一、本轮验证结果

1. 后端编译

3. RESTful API 与基础链路

- 已确认后端使用 Spring MVC @RestController，并提供 /api/v1 版本化 RESTful API。

- 登录接口在独立内存 H2 实例中成功返回 accessToken；未登录访问受保护的数据集接口返回 403；携带 JWT 后数据集列表接口返回 200。

- 图表推荐能够根据字段类型返回柱状图、饼图、散点图、直方图等建议。
- 8080 端口当时被已有 Java 进程占用，因此测试使用了 8082 独立端口；不要直接停止未知进程。

4. 本轮发现的真实缺陷

- 安全扫描接口对含有手机号、邮箱、姓名、地址字段的 CSV 执行时失败，数据库报错：MATCH_TYPE 字段长度为 VARCHAR(20)，但实际规则值 FIELD_NAME_AND_CONTENT 长度为 22。需要统一数据库字段长度、枚举值或缩短规则值，并补充迁移脚本和回归测试。
- 安全扫描失败后应确保扫描任务状态、错误信息和事务数据一致，不能只返回 400 而留下不明确的半成品记录。

### 二、本轮发现的反复未完成问题及具体实现方法

#### P0-1：默认启动配置仍不具备可验收性

问题：默认 h2 配置使用 `jdbc:h2:file:./data/river_agi;AUTO_SERVER=TRUE`。本地旧数据库文件记录了不可连接的 H2 server 地址，应用在数据库初始化阶段失败；默认 JWT 密钥长度也曾触发 JJWT `WeakKeyException`。应用不能做到开箱启动。

实现方法：

1. 开发 profile 使用 `jdbc:h2:mem:river_agi;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE`，持久化测试另设明确的 file profile，不在默认 profile 中使用 `AUTO_SERVER=TRUE`。
2. JWT 密钥只从 `JWT_SECRET` 读取，启动时校验 Base64 解码后不少于 32 字节；缺失或不足时给出明确配置错误。
3. 将 `ENCRYPTION_MASTER_KEY`、数据库密码和 AI Key 全部改为必填环境变量或密钥管理服务，示例配置只能放占位符。
4. 提供可重复的启动命令、数据库初始化命令和清理测试库说明，确保新环境可复现。

#### P0-2：异步解析的 HTTP 结果、任务状态和最终数据不一致

问题：本轮调用 `POST /api/v1/datasets/1/parse` 首次返回 HTTP 500，但稍后查询数据集时状态已经变成 `PARSED`。这说明请求层没有稳定返回 taskId，后台任务和异常处理没有形成可追踪闭环。

实现方法：

1. 解析接口只负责创建任务并立即返回 `taskId`，统一返回 `202 Accepted` 或统一业务成功码。
2. 后台任务状态必须包含 `PENDING/RUNNING/SUCCESS/FAILED/CANCELLED`、进度、开始时间、结束时间、错误码和错误信息。
3. 任务执行成功后在同一事务中更新数据集状态、行数、列数、schema 和 preview；失败时写入失败原因并保证不留下半成品状态。
4. 增加 `GET /api/v1/tasks/{id}`、失败重试和幂等校验的集成测试，验证“提交、轮询、成功/失败、重试”四种结果。

#### P0-3：安全扫描仍然返回 500

问题：包含手机号、邮箱、身份证号、姓名和地址的真实 Excel 扫描仍返回 HTTP 500。历史上已确认 `MATCH_TYPE` 字段长度不足；本轮仍不能以真实扫描成功作为合同验收证据。

实现方法：

1. 将 `match_type` 统一为足够长度的字符串或数据库枚举，补充 Flyway/H2/MySQL 两套迁移脚本，禁止只修改实体类不修改数据库。
2. 扫描前读取字段名和完整单元格内容；规则至少覆盖手机号、身份证号、银行卡号、邮箱、姓名、地址、密码和经营敏感字段。
3. 每条命中记录保存字段名、命中类型、命中数量、风险级别、置信度、规则版本、脱敏示例和整改建议。
4. 扫描失败必须返回可定位的错误码，并将任务置为 `FAILED`；成功后必须能通过风险查询接口查到真实记录。
5. 增加真实 XLSX、CSV、空文件、非法格式和超大文件的安全扫描集成测试。

#### P0-4：质量分析没有正确反映测试文件中的异常

问题：质量结果虽然返回成功，但测试文件明确含有重复行、空值、离群值、负价格和非法日期，结果却出现 `duplicateRows=0`、`nullCells=0`，与输入事实不一致；`emptyCells` 与列级空值统计也不完全一致。当前评分不能作为合同质量验收证据。

实现方法：

1. 统一空值、空字符串、非法格式和缺失字段的判定口径，所有指标从同一份解析后的完整记录计算。
2. 用稳定的整行哈希或主键组合检测重复行，返回重复组数量、重复行数量和示例行号。
3. 对日期、数值、手机号、邮箱和业务规则进行字段级校验，记录异常值、异常类型、行号和原始值。
4. `totalRows`、`totalCells`、`nullCells`、`emptyCells`、`duplicateRows` 和各列统计必须满足可复算关系；补充断言测试。
5. 质量评分必须使用版本化规则，并在结果中返回规则版本和每项扣分明细。

#### P0-5：AI 对话仍不是实际工具调用闭环

问题：`ChatService` 当前把工具名称写入系统提示词，但没有看到后端工具注册和工具执行链路。使用占位 Key 时能正确返回 401，但即使配置真实 Key，也不能据此证明 `inspectDataset`、质量分析、安全扫描、图表和预测工具真实执行。

实现方法：

1. 将每个分析能力实现为白名单工具 Bean，使用 Spring AI tool/function calling 显式注册到 `ChatClient`。
2. 工具参数只允许 datasetId、任务参数和受控字段，工具内部再次执行用户身份、租户和资源权限校验，禁止 AI 直接访问数据库或执行 SQL。
3. 工具返回结构化 JSON、任务 ID或图表配置；AI 只负责解释真实返回值，不允许补造统计数字。
4. 无 AI Key 时应用必须正常启动，AI 接口返回“AI 未配置”；有 Key 但调用失败时返回明确错误并记录审计。
5. 使用 Mock AI Provider 做自动化测试，验证一次用户消息确实触发指定工具、工具参数正确、工具失败可追踪；再用真实 Key 做人工验收。

#### P0-6：预测、报告和异常数据处理仍未形成最终闭环

问题：趋势图可以返回非法日期 `2026/99/99`；含异常日期的数据创建预测任务和生成报告均返回 500，错误没有转化为可理解的参数校验信息。已有多种本地算法，但尚未提供验证集指标和稳定的失败任务结果。

实现方法：

1. 预测创建前校验时间字段、目标字段、日期格式、排序、最小样本量、缺失值和非数值目标，失败返回明确 4xx 错误码及行号。
2. 预测参数必须支持 forecastDays、算法、窗口和置信区间，不得固定为 30 天；预测任务必须返回 taskId 并支持轮询。
3. 使用时间序列训练集/验证集切分或滚动交叉验证，记录 MAE、RMSE、MAPE、R2、训练范围、参数、模型版本和数据版本。
4. 报告必须读取真实质量、安全、图表和预测结果；任一依赖失败时报告状态为 `FAILED` 并保存原因，禁止生成固定结论。
5. 增加合法数据、缺失日期、非法日期、负数、样本不足和大数据量的预测/报告集成测试。

#### P0-7：资源权限和审计覆盖仍需逐接口证明

问题：本轮仅确认了数据集认证拦截，尚未形成所有资源的越权测试证据。部分 Controller 仍直接按 ID 查询，报告、预测、标注、聊天会话、风险结果、图表和导出接口必须逐项确认资源归属。

实现方法：

1. 所有资源读取、修改、删除、下载、导出、脱敏和任务查询统一经过 ResourceAccessValidator，校验 userId/tenantId/角色和资源归属。
2. 对用户 A、用户 B、管理员分别执行同一组 ID 访问测试，断言状态码、响应体和错误信息均不泄露资源内容。
3. 通过 AOP 或统一拦截器覆盖上传、分析、扫描、脱敏、标注、审核、仲裁、预测、重训、报告、AI 工具和备份恢复。
4. 审计记录必须包含用户、租户、资源、动作、请求路径、IP、traceId、成功/失败和错误原因，敏感原文不得写入日志。

### 三、合同目标完成度判断

已具备但仍需证据固化：前后端分离、Spring Boot/Vue、Controller-Service-Mapper-Entity 分层、RESTful API 基础路径、JWT 登录、上传预览、基础分析、图表推荐、多种预测算法、标注基础接口、备份记录和 Docker 基础文件。

部分完成：数据标注质量闭环、多媒体标注、真实安全大数据扫描、脱敏文件、异步任务、AI 工具调用、预测评估、报告生成、权限审计和备份恢复。

尚不能认定符合合同最终要求：默认配置可重复启动、真实敏感扫描成功、异常数据质量结果正确、真实 AI 工具调用、验证集预测指标、200 并发、1.5 秒常规响应、5 秒复杂任务提交、百万级分析、千万级标注查询、总体 80%/关键业务 100%覆盖率、TLS/密钥轮换/恢复演练、Docker 生产部署和完整交付文档。

### 四、是否可以进行最后一轮

可以进行“最后一轮整改”，但不能直接进入最终验收，也不能宣称已经满足合同全部要求。最后一轮应限定为“P0 缺陷修复 + 合同验收证据补齐”，不再无边界增加新功能。

进入最终验收准备的硬性条件：

1. h2 和生产配置在全新环境可以启动，JWT、数据库、加密和 AI 密钥不使用弱默认值。
2. 真实 Excel/CSV 全流程成功：上传、异步解析、质量分析、安全扫描、脱敏、图表、标注、预测、报告和审计。
3. 安全扫描不再 500，质量结果能正确识别重复、空值、非法日期、离群值和敏感字段。
4. AI 工具至少完成 Mock 自动化闭环，并用真实 Key 完成一次人工验收；无 Key 不阻塞非 AI 功能。
5. 所有核心资源完成双用户越权测试，敏感操作有审计记录。
6. 提供接口集成测试、前端关键流程测试、覆盖率、性能、安全、备份恢复和 Docker 部署报告。

最终结论：当前版本是“已具备核心模块、但仍存在关键闭环缺陷的集成验证版”。可以开启最后一轮整改；完成上述硬性条件并取得可复核测试证据后，才可以进入合同最终验收。
