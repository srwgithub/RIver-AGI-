# RIver AGI TRAE 第十五轮整改说明

## 一、复查结论

本轮未修改业务代码，使用桌面文件 `RIver_AGI_下一轮综合测试数据.xlsx` 对本地后端进行了真实接口复核。该文件包含 25 行、16 列数据，并包含空值、重复行、异常数值、非法日期、手机号、邮箱、身份证号、姓名和地址。

已验证：

1. JWT 注册、登录正常，登录返回 Bearer Token。
2. Excel 上传成功，数据集最终可解析，行数 25、列数 16，预览可查询。
3. 数据质量分析接口可以返回完整性、唯一性、准确性、有效性和总体评分。
4. 图表推荐和趋势图接口可以返回真实字段及数据。
5. 未携带 Token 访问数据集接口返回 HTTP 403，携带本人 Token 返回 200。
6. AI 会话可以创建；使用占位 API Key 发送消息时返回 DeepSeek 401，没有伪造 AI 结果。
7. 已有 53 个单元测试通过，但尚不能代替接口、集成、性能和安全验收。

## 二、反复未完成问题及具体实现方法

### 1. H2 默认启动不稳定

现象：默认 h2 配置使用 `jdbc:h2:file:./data/river_agi;AUTO_SERVER=TRUE`，旧数据库文件可能记录不可连接的 H2 server 地址；弱 JWT 密钥曾导致 `WeakKeyException`。

实现方法：

- 开发 profile 改用内存 H2：`jdbc:h2:mem:river_agi;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE`。
- 持久化 H2 单独设置 file profile，不使用默认 `AUTO_SERVER=TRUE`。
- JWT_SECRET 改为必填环境变量，启动时校验不少于 32 字节。
- ENCRYPTION_MASTER_KEY、数据库密码和 AI Key 统一使用环境变量或密钥管理服务。
- 提供全新环境可重复执行的启动和初始化说明。

### 2. 异步解析返回结果与实际状态不一致

现象：调用 `POST /api/v1/datasets/{id}/parse` 首次返回 HTTP 500，但稍后查询数据集时状态已经变为 `PARSED`，说明后台处理和 HTTP 错误处理没有形成稳定闭环。

实现方法：

- 解析接口立即返回 taskId，不在 HTTP 请求内等待大文件处理。
- 任务状态统一为 `PENDING/RUNNING/SUCCESS/FAILED/CANCELLED`。
- 保存进度、开始时间、结束时间、错误码和错误原因。
- 成功时事务性更新行数、列数、schema、preview 和数据集状态。
- 失败时状态必须为 FAILED，不能留下半成品数据。
- 补充任务查询、重试、取消和幂等集成测试。

### 3. 安全扫描仍返回 HTTP 500

现象：使用真实测试 Excel 执行敏感数据扫描仍返回 HTTP 500。历史问题包括 `MATCH_TYPE` 字段长度不足。

实现方法：

- 将 match_type 统一为足够长度的字符串或数据库枚举。
- 同步补充 Flyway、H2 和 MySQL 数据库迁移脚本。
- 同时检查字段名和单元格内容。
- 至少识别手机号、身份证号、银行卡号、邮箱、姓名、地址、密码和经营敏感字段。
- 保存字段名、类型、命中数量、风险级别、置信度、规则版本、脱敏示例和整改建议。
- 扫描失败写入 FAILED 状态和明确错误码；成功后风险查询接口必须能查到记录。

### 4. 质量分析结果与测试数据事实不一致

现象：测试文件存在重复行、空值、离群值、负价格和非法日期，但结果出现 `duplicateRows=0`、`nullCells=0`，部分统计口径也不一致。

实现方法：

- 统一空值、空字符串、非法格式和缺失字段的判定规则。
- 使用整行哈希或主键组合检测重复行，返回重复组和行号。
- 对日期、数值、手机号、邮箱和业务规则进行字段级校验。
- 返回异常类型、行号、原始值和整改建议。
- 保证 totalRows、totalCells、nullCells、emptyCells、duplicateRows 可复算。
- 质量评分使用版本化规则，并返回各项扣分明细。

### 5. AI 对话未形成真实工具调用闭环

现象：ChatService 中主要是把工具名称写入系统提示词，尚未证明后端工具被注册并真实执行。

实现方法：

- 将数据画像、质量分析、安全扫描、图表和预测实现为白名单工具 Bean。
- 通过 Spring AI tool/function calling 显式注册工具。
- 工具内部再次校验用户、租户、数据集权限和参数范围。
- 禁止 AI 直接访问数据库或执行任意 SQL。
- 工具返回结构化 JSON、任务 ID或图表配置，AI 不得编造数据。
- 无 AI Key 时非 AI 功能仍可启动，AI 接口返回明确的“AI 未配置”。
- 用 Mock AI Provider 验证工具是否真实触发，再用真实 Key 做人工验收。

### 6. 预测、报告和异常数据处理不完整

现象：趋势图可以返回非法日期 `2026/99/99`；含异常日期的数据创建预测任务和生成报告返回 500，未转化为明确的参数错误。

实现方法：

- 创建预测前校验时间字段、目标字段、日期格式、排序、缺失值、数值类型和最小样本量。
- 非法输入返回明确 4xx 错误码、字段名和行号。
- 支持 forecastDays、算法、窗口和置信区间，不能固定预测 30 天。
- 使用时间序列验证集或滚动交叉验证。
- 记录 MAE、RMSE、MAPE、R2、训练范围、参数、模型版本和数据版本。
- 报告必须读取真实质量、安全、图表和预测结果，依赖失败时报告状态为 FAILED，禁止使用固定结论。

### 7. 资源权限和审计覆盖需要逐接口证明

现象：本轮仅验证了数据集接口的认证拦截，报告、预测、标注、聊天会话、风险、图表和导出接口仍需逐项验证资源归属。

实现方法：

- 所有资源读取、修改、删除、下载、导出、脱敏和任务查询统一经过 ResourceAccessValidator。
- 分别使用用户 A、用户 B 和管理员执行同一组资源 ID 访问测试。
- 越权时不能泄露资源名称、字段、结果或敏感数据。
- 审计覆盖上传、分析、扫描、脱敏、标注、审核、仲裁、预测、重训、报告、AI 工具和备份恢复。
- 审计记录包含用户、租户、资源、动作、路径、IP、traceId、结果和错误原因。

## 三、合同符合性判断

已具备但需要补充证据：前后端分离、Spring Boot/Vue、Controller-Service-Mapper-Entity 分层、RESTful API、JWT 登录、上传预览、基础分析、图表推荐、多种预测算法、标注基础接口、备份记录和 Docker 基础文件。

部分完成：数据标注质量闭环、多媒体标注、安全扫描、脱敏文件、异步任务、AI 工具调用、预测评估、报告生成、权限审计和备份恢复。

目前不能认定满足合同最终要求：真实敏感扫描、异常数据质量准确性、真实 AI 工具调用、验证集预测指标、200 并发、1.5 秒常规响应、5 秒复杂任务提交、百万级分析、千万级标注查询、总体 80%/关键业务 100% 覆盖率、TLS、密钥轮换、恢复演练、Docker 生产部署和完整交付文档。

## 四、是否可以进入最后一轮

可以进行最后一轮整改，但不能直接进入最终验收。最后一轮应限定为“P0 缺陷修复 + 合同验收证据补齐”，不再无边界增加新功能。

进入最终验收准备前必须满足：

1. 全新环境可以启动，不能使用弱 JWT、数据库、加密和 AI 默认密钥。
2. Excel/CSV 能完成上传、异步解析、质量分析、安全扫描、脱敏、图表、标注、预测、报告和审计全流程。
3. 安全扫描不再返回 500，质量结果能识别重复、空值、非法日期、离群值和敏感字段。
4. AI 工具完成 Mock 自动化闭环和一次真实 Key 人工验收；无 Key 不阻塞非 AI 功能。
5. 所有核心资源完成双用户越权测试，敏感操作有完整审计记录。
6. 具备接口集成测试、前端关键流程测试、覆盖率、性能、安全、备份恢复和 Docker 部署报告。

最终结论：当前系统是“已具备核心模块、但存在关键闭环缺陷的集成验证版”。可以开启最后一轮整改；完成以上条件并取得可复核证据后，才可以进入合同最终验收。
