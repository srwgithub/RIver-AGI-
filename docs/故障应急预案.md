# RIver AGI 故障应急预案

## 1. 通用流程

发现故障 → 建立事件记录 → 判断影响范围 → 保护数据和日志 → 恢复服务 → 验证核心链路 → 通知相关人员 → 复盘和补救。

任何恢复操作先确认备份编号和审批人，不删除原始备份、不执行 `docker compose down -v`，不直接修改生产数据库。

## 2. 场景处理

### Java 后端不可用

检查 `./ops/health-check.sh`、端口 8080、最近 200 行日志和数据库连接。若为进程退出，使用发布版本重新启动；若为数据库连接耗尽，先限流并检查连接池、慢 SQL。恢复后验证登录、数据集列表、预测健康和审计日志。

### Python 引擎不可用

检查 5001 端口、虚拟环境和模型依赖；确认 Java 的 `DL_ENGINE_ENABLED=true`、`DL_ENGINE_URL=http://127.0.0.1:5001`。普通 Java 算法可继续运行，深度学习任务暂停并保留失败任务状态，Python 恢复后再重试。

### MySQL 故障

停止写入或切换只读，保留错误日志和 binlog；确认磁盘、连接数和 InnoDB 状态。使用最近一次经过验证的备份恢复到隔离实例，完成数据抽样校验后再切换，禁止在未验证时覆盖原库。

### 磁盘满或上传失败

确认 `uploads/`、`backups/`、模型目录和日志占用；按保留策略清理临时文件和已归档日志。禁止删除未归档备份、生产模型和审计日志。

### 权限或安全事件

立即禁用受影响账号、保留审计日志和访问源信息，轮换 JWT/DeepSeek/对象存储密钥，检查备份和导出记录。完成风险扫描后由管理员复核恢复权限。

## 3. 恢复验收

服务恢复后必须执行：`./ops/health-check.sh`、管理员登录、数据集读取、预测引擎健康检查、性能监控查询、备份列表查询和审计日志查询。深度学习故障恢复还需使用测试数据提交一次训练状态检查。

## 4. 事件复盘模板

记录事件编号、发现时间、恢复时间、影响用户、根因、时间线、临时措施、永久修复、数据是否丢失、监控是否提前告警和责任人。
