# RIver AGI 监控与告警方案

## 1. 监控范围

- 服务可用性：前端、Java `/actuator/health`、Python `/health`、MySQL、Redis、MinIO、RabbitMQ。
- JVM/主机资源：CPU、堆内存、磁盘使用率和进程状态。
- 预测运行指标：任务成功/失败、推理延迟、吞吐量、模型训练状态。
- 业务指标：上传、清洗、标注、质检、仲裁、导出、预测、评估和备份结果。
- 安全指标：登录失败、权限拒绝、敏感数据风险、备份恢复和审计操作。

## 2. 现有接口

登录后使用 Bearer Token 访问：

| 用途 | 接口 |
| --- | --- |
| Java 服务 | `GET /actuator/health`、`GET /actuator/metrics` |
| Python 服务 | `GET http://127.0.0.1:5001/health` |
| 预测引擎连通性 | `GET /api/v1/predictions/health` |
| 性能汇总 | `GET /api/v1/predictions/monitoring/summary` |
| 性能采样 | `GET /api/v1/predictions/monitoring/samples` |
| 运行告警 | `GET /api/v1/predictions/monitoring/alerts` |
| 告警处理 | `POST /api/v1/predictions/monitoring/alerts/{id}/resolve` |
| 审计日志 | `GET /api/v1/audit/logs` |

Java 业务执行会记录延迟、吞吐、成功/失败状态；超过延迟 200ms、CPU 85%、内存 85% 或任务失败会生成运行告警。

## 3. 告警级别与响应

| 级别 | 条件 | 响应时限 | 处理方式 |
| --- | --- | ---: | --- |
| ERROR | Java/Python 不可用、连续任务失败、数据库不可用 | 15 分钟 | 值班人确认、保留现场、启动应急预案 |
| WARNING | CPU/内存超过 85%、延迟超过 200ms、磁盘超过 80% | 2 小时 | 降载、扩容、清理日志或模型缓存 |
| INFO | 发布、备份、恢复、权限变更 | 1 个工作日 | 审计核对和归档 |

系统内告警在监控页面展示并可确认关闭。生产环境建议在监控采集器中轮询上述接口，将 ERROR/WARNING 转发到企业微信、钉钉、邮件或 PagerDuty；通知服务不得把 Token、密码或 API Key 写入消息。

## 4. 日志分析

统一保留 Java、Python、Nginx 和容器日志，生产建议按天轮转、保留 30 天，审计日志按合规策略保留 730 天。重点检索：`ERROR`、`Exception`、`401`、`403`、`timeout`、`deadlock`、`OutOfMemoryError`、`training failed`。

建议日志字段：时间、服务、请求 ID、用户、租户、接口、状态码、耗时、任务 ID、错误码。脱敏后才允许导出或发送到集中日志平台。

## 5. 可用率统计

可用率按月统计：`(统计周期总分钟 - 不可用分钟) / 统计周期总分钟 × 100%`。99.5% 是持续运行数据，不可由一次压测证明。每次宕机记录开始/恢复时间、原因、影响范围和修复动作。
