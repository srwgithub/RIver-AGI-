# RIver AGI 运维手册

## 1. 服务清单

| 服务 | 默认端口 | 进程/容器 | 健康检查 |
| --- | ---: | --- | --- |
| Vue 前端 | 3000 | Node/Vite 或 Nginx | `GET /` |
| Java 后端 | 8080 | Spring Boot | `GET /actuator/health` |
| Python 预测引擎 | 5001 | Flask/Wsgi | `GET /health` |
| MySQL | 3306 | MySQL 8 | `mysqladmin ping` |
| Redis | 6379 | Redis 7（可选） | `redis-cli ping` |
| MinIO | 9000/9001 | MinIO（可选） | `/minio/health/live` |
| RabbitMQ | 5672/15672 | RabbitMQ（可选） | 管理台或 `rabbitmq-diagnostics` |

## 2. 测试环境部署

1. 安装 Java 21、Maven 3.9、Node.js 20、Python 3.10、MySQL 8。
2. 创建 `river_agi` 数据库，配置 `backend/.env.local`。该文件只放在部署机，不进入 Git。
3. 安装 Python 依赖并构建 Java：

```bash
cd backend/prediction-engine
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cd ..
mvn -DskipTests package
```

4. 启动后端和 Python：

```bash
./start-local.sh
```

5. 另开终端启动前端：

```bash
cd frontend
npm ci
npm run dev -- --host 0.0.0.0
```

## 3. 生产环境部署

生产环境建议使用以下拓扑：Nginx/网关 → Vue 静态文件和 Java API；Java 与 Python 使用 systemd 或 Docker `restart: unless-stopped` 托管；MySQL、Redis、MinIO、RabbitMQ 使用独立持久化卷。

生产部署必须替换：

- 独立 MySQL 账号，禁止使用 root。
- 随机 `JWT_SECRET`、`ENCRYPTION_MASTER_KEY` 和 DeepSeek Key。
- `LOG_LEVEL=INFO`，关闭调试日志。
- HTTPS、数据库白名单、内网绑定和防火墙策略。
- 上传目录、备份目录、模型目录的独立磁盘和权限。

前端生产构建：

```bash
cd frontend
npm ci
npm run build
```

将 `frontend/dist` 交给 Nginx 托管，并把 `/api/` 反向代理到 `127.0.0.1:8080`。Nginx 必须配置 SPA fallback 到 `index.html`，否则刷新子路由会出现 404。

## 4. 日常操作

```bash
# 服务状态
./ops/health-check.sh

# Java 日志（systemd）
journalctl -u river-agi-java -f

# Python 日志（systemd）
journalctl -u river-agi-python -f

# Docker 方式
cd backend && docker compose ps
cd backend && docker compose logs --tail=200 app
```

备份恢复从前端“安全审计中心 → 备份恢复”进入；命令行恢复前必须确认备份编号、目标数据库和审批人，禁止直接覆盖生产数据。

## 5. 发布与回滚

1. 发布前执行 `mvn -DskipTests package`、`npm run build` 和 `./ops/health-check.sh`。
2. 保存当前 JAR、前端 `dist`、配置版本和数据库 Flyway 版本。
3. 发布后检查登录、预测健康、Python 健康、备份列表和审计日志。
4. 发生回滚时恢复上一版 JAR/dist；数据库只执行已验证的向前迁移，不使用破坏性回退。

## 6. 责任与安全

运维人员负责服务可用性、备份和告警；管理员负责账号权限和审计；业务人员只使用业务页面。所有生产操作通过权限账号完成并保留审计记录。

## 7. 生产化工具

- 使用 `backend/src/main/resources/application-prod.yml` 启动生产 profile；生产环境必须注入 `backend/.env.example` 中的真实密钥。
- 使用 `backend/docker-compose.yml` 启动 Java、Python、MySQL、Redis、RabbitMQ 和 MinIO；Python 引擎健康后 Java 才启动。
- 使用 `ops/nginx.conf.example` 配置 HTTPS、API 代理和前端子路由回退。
- 使用 `ops/security-baseline.sh` 检查生产文件和源码中的明显敏感信息。
- 使用 `qa/performance_smoke.py --users 200 --requests 200` 生成预检数据；正式性能报告必须在目标环境执行。
